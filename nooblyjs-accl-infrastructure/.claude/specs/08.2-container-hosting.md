# 8.2 Container hosting on shared VMs

Needs: 8.1. Today an app runs alone on a VM a person chose (architecture §9). A hosting platform needs many tenants'
containers per VM, limits that hold, and a scheduler that picks the VM.

## Requirements

1. **R1** Operators create a **host pool** per region (account, region, VM size, min/max hosts). The pool's VMs are
   ordinary VM records with `role: host` and `pool: <name>`, hidden from the VM list like database VMs.
2. **R2** Each instance runs as a container with `--cpus=<plan.cpu>` and `--memory=<plan.memoryMb>m`
   (`--memory-swap` equal, no swap), `--pids-limit 512`, a read-only root filesystem where the runtime allows, no
   privileged mode, no host networking, dropped capabilities, user namespaces on.
3. **R3** Placement reserves the plan's CPU and memory on a host; a host is never reserved beyond
   `allocatable = vm total − system reserve (0.25 vCPU, 512 MB)`. Instances of one workload go to different hosts when
   the pool has more than one.
4. **R4** When no host has room, placement grows the pool by one VM (up to `max`), or the operation fails with
   `quota` and the plain reason "Region af-south-1 is full", which the launcher shows.
5. **R5** Each tenant gets its own Docker network per host (`noobly-t-<hash>`); `private` workloads are reachable at
   `<name>.<tenant>.internal` from the tenant's other workloads and from nothing else. Cross-host traffic for
   private workloads goes over the cloud's private network to the host's private IP, filtered per tenant (8.4 ingress
   for public traffic).
6. **R6** `job` workloads run a one-off container that is removed when it exits; exit code, duration and peak memory
   are recorded; a job never runs twice at once.
7. **R7** Container crashes are restarted by Docker (`--restart on-failure:5`); the crash, the exit code and the
   restart count are events (`infrastructure.instance.crashed`).
8. **R8** Suspend stops and removes a workload's containers and frees its reservations; resume places them again.
9. **R9** A drained host (operator action) takes no new instances and its instances are moved one by one with the
   rolling rules of 8.4 before it is deleted.

## Design

### Records

- `pools/<name>.md`: `account`, `region`, `zones[]`, `size`, `min`, `max`, `systemReserve`, `status`.
- VM records gain `role: host`, `pool`, `allocatable` `{ cpu, memoryMb }`, `reserved` `{ cpu, memoryMb }`.
- `instances/<tenant>/<workload>/<id>.md`: `host`, `container`, `port` (host-local, from the host's range
  20000–29999), `image`, `status` (`starting|running|stopped|crashed`), `restarts`, `startedAt`.

### Placement (`src/services/placement.js`)

Pure function over records, so it is unit tested without a cloud: filter hosts by pool region and status → score by
least reserved CPU after placement (spread), tie-break by fewest instances of the same workload, then by name →
reserve under the pool lock. Returns `{ host }` or `{ grow: true }` or `{ full: true }`.

### Steps

`instance.place` (reserve) · `instance.start` (pull image, create tenant network if absent, `docker run` with the
limits, labels `noobly-tenant`, `noobly-workload`, `noobly-instance`) · `instance.check` (health, 8.4) ·
`instance.stop` (stop, remove, release reservation). `pool.grow` reuses `vm.launch` steps 1–2 with the host
cloud-init (Docker, Caddy off, the telemetry collector of 8.5). `host.drain` moves instances then deletes the VM.

### Remote

New fixed scripts in `src/remote/scripts/`: `container-run.sh`, `container-stop.sh`, `tenant-network.sh`,
`job-run.sh`. Same rules as architecture §9: positional, validated arguments; env through a 0600 `--env-file`.

### Mock

A mock host tracks reservations and containers in the mock cloud state; `failAt: 'instance.start'` and
`outOfBand: { crash: <instance> }` drive the crash path.
