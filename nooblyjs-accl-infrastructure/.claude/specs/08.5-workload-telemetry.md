# 8.5 Workload telemetry

Needs: 8.2 (and 8.4 for requests and bandwidth). The launcher (NooblyJS Cloud) draws the charts and the log viewer
and keeps history; this accelerator collects and hands over.

## Requirements

1. **R1** Every 10 s, for every running instance: CPU used (vCPU), memory used (MB), network in/out (bytes), with the
   plan's limits alongside (`{ value, unit, limit }`).
2. **R2** Requests (count, by status class) and bytes out per workload per 10 s from ingress (8.4).
3. **R3** Every line a container writes to stdout/stderr reaches the launcher within 3 s, tagged
   `{ tenantId, workload, instance, at, stream, line }`; lines over 16 KB are cut and marked.
4. **R4** Delivery is in process: `services.platform.telemetry.subscribe({ onMetrics, onLogs })` and as
   `infrastructure.telemetry.*` events on `eventEmitter`; the accelerator keeps only a short buffer
   (last 1,000 lines and 15 min of samples per instance) for operators.
5. **R5** If the collector loses a host, samples show a gap and logs resume from the last timestamp seen (no duplicates
   beyond one second, no silent loss for gaps under 5 min).
6. **R6** Collection never needs SSH per page view; it is continuous per host and its cost is bounded (≤ 5% of a
   host's CPU).

## Design

**v1 collector (SSH):** one long-lived SSH session per host (the pooled runner) running `telemetry.sh`, which streams
`docker stats --no-stream` every 10 s and `docker logs --follow --timestamps --since <cursor>` per labelled container
as NDJSON on stdout. The server side (`src/services/telemetry.js`) parses, tags with the instance record, buffers and
publishes. Cursors per container are saved every 30 s so a restart resumes with `--since`.

**Later (open decision O4):** an on-host agent that pushes over HTTPS; the publish side stays the same.

**Usage:** an hourly job sums reserved CPU·hours and memory GB·hours per instance and bytes out per workload into
`usage/<tenant>/<yyyy-mm>.yaml`, read by `services.platform.usage()` (billing in the launcher and the payments
accelerator).

**Mock:** the mock host produces synthetic samples (a sine around 40% with noise) and log lines from a seeded script,
so the NooblyJS Cloud screens can be built offline.
