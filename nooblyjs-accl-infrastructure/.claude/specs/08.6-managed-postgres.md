# 8.6 Managed Postgres

Needs: phase 5 (databases: the managed MySQL pattern). Postgres joins MySQL and MongoDB as an engine. It is useful to
the accelerator's own product too, so it also appears on the Databases screen.

## Requirements

1. **R1** Engine `postgres`, versions 16 (default) and 15, managed by the cloud: Cloud SQL for PostgreSQL or RDS for
   PostgreSQL. Tiers Starter / Standard / Performance as for MySQL; storage auto-grow; HA (regional / Multi-AZ).
2. **R2** Private only, with the same same-cloud rule as MySQL (architecture D10); for platform workloads, the
   database is reachable only from the tenant's hosts' private IPs **and** only by the tenant's containers (a per-tenant
   database user and `pg_hba`-equivalent network rule; the host firewall forwards 5432 only from that tenant's network).
3. **R3** Daily backups at a chosen time, kept 7/14/30 days, plus **point-in-time recovery** to any second within the
   retention (Cloud SQL PITR, RDS automated backups) into a new database.
4. **R4** One optional **read replica** in the same region; its connection string is a second linked variable
   (`DATABASE_REPLICA_URL`).
5. **R5** Connection string `postgres://<user>:<password>@<private host>:5432/<db>?sslmode=require`, revealed only by
   the audited reveal (product §7) or linked into a workload's env as a secret.
6. **R6** Metrics: CPU, connections (of max), storage used, read/write IOPS, replication lag.
7. **R7** Platform API: `services.platform.databases.create(tenantId, { engine: 'postgres', … })` with the same
   operation and event model as workloads (8.1).

## Design

Engine module `src/services/engines/postgres-managed.js` beside `mysql-managed.js`, sharing the managed-database
steps (`db.create`: Network access · Create the server · Admin user and password · Backups · Allow VMs).
Provider contract `databases.create(spec)` gains `engine: 'postgres'`; adapters map tiers to
`db-custom-*` (Cloud SQL) and `db.t4g.*` / `db.m6g.*` (RDS); `rds.force_ssl=1` parameter group; Cloud SQL
`ipConfiguration.requireSsl`. New calls: `databases.restoreToTime(ref, at, newSpec)`, `databases.replica.create(ref)`,
`databases.replica.remove(ref)`. Catalogue gains Postgres prices (`asOf` dated). The Create a database page gains a
**Postgres** engine card (MySQL purple, MongoDB green, Postgres ink badge — a new `--inf-engine-postgres` token).

**Mock:** a mock Postgres resource with backups and a PITR window; restore produces a new resource.

### Databases the platform runs itself (decision, 2026-11-22)

For a launcher's tenants on a **local site** (8.9) the platform runs Postgres itself, before the cloud adapters:

- **Where.** The operator names one Postgres server for the site: `local.postgres.url` (or `INFRA_LOCAL_POSTGRES_URL`),
  an admin login, never logged or stored. `src/platform/postgres-local.js` makes each database there: a database and a
  login role of the same name (`nb_<name>_<hash of tenant/name>`) that owns it, `NOSUPERUSER NOCREATEDB NOCREATEROLE`,
  a connection limit from the plan, and `REVOKE ALL ON DATABASE … FROM PUBLIC` with CONNECT granted to its role only.
- **Reach (R2).** Containers reach the server through the agent's **relay** (`agent/relay.js`, commands `relay.ensure`
  and `relay.remove`) on the tenant network's gateway address. Docker answers a gateway address from every bridge
  network, so the relay drops a connection whose source is outside that network's subnet, then reads the Postgres
  startup message and forwards it only when its database is one of the tenant's and its user is that database's own
  role (anything else gets a FATAL 28000 from the relay; the server never sees it). TLS is declined on this hop (it never
  leaves the machine). The agent relays only to targets it was started with (`--relay-target host:port`).
- **Links (R5).** A workload's `{ key, link: { database } }` resolves when a container (or a job's run, now on the
  tenant network too) starts: the relay is opened on that server's tenant network with the tenant's databases, and the
  variable gets `postgres://<role>:<password>@<gateway>:<port>/<db>?sslmode=disable`. A link to another tenant's
  database, or one in another region, is refused when the workload is created or changed.
- **Backups (R3, local).** `pg_dump -Fc` daily at the database's `backupTime` (UTC) and on demand, the last 7 kept
  under `platform-databases/<tenant>/<name>/backups`; a restore makes a new database with `pg_restore --role`. No PITR,
  replicas or HA locally.
- **API (R7).** `services.platform.databases`: create, list, get, connection, stats (size, connections, limits), update
  (connections at once, backup time), remove, backups, backup, restore; operations `database.create`, `.delete`,
  `.backup`, `.restore`; events `infrastructure.database.status`, `.backed_up`, `.backup_failed`, `.deleted`. Cloud
  regions use the mock engine until 8.6.2 and 8.6.3.
