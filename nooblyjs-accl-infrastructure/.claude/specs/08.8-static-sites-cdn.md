# 8.8 Static sites and CDN

Needs: phase 4 (buckets), 8.3 (builds). Overlaps roadmap 7.3 (bucket custom domains over HTTPS): this spec delivers
7.3's mechanism for platform sites, and 7.3 reuses it for the product's buckets.

## Requirements

1. **R1** A `static` workload builds with its runtime and build command and publishes a directory (`publishDir`,
   default `dist`) — no containers keep running.
2. **R2** Each deploy uploads to a new prefix (`<tenant>/<site>/<deployId>/`) in the region's static bucket, then
   switches the CDN origin path atomically; rollback is switching back. Old prefixes beyond the last 5 are deleted.
3. **R3** Served through **Cloud CDN** (backend bucket behind an HTTPS load balancer) or **CloudFront** (S3 origin with
   origin access control), on the platform host name and custom domains with managed certificates.
4. **R4** Cache: HTML `no-cache`, hashed assets `max-age=31536000, immutable`; deploys purge HTML paths.
5. **R5** SPA fallback (`index.html` for unknown paths) and redirects/headers from a `_redirects` / `_headers` file.
6. **R6** Metrics per site: bandwidth (of the plan's allowance), requests, cache hit rate.

## Design

Provider contract gains `cdn: { ensureSite(spec), setOrigin(ref, prefix), purge(ref, paths), addDomain(ref, host),
metrics(ref) }`. GCP: one global external HTTPS load balancer per install with a URL map entry per site, backend
bucket with Cloud CDN, Google-managed certificates. AWS: one CloudFront distribution per site (or per tenant when
limits bite), OAC on the bucket, ACM certificate in us-east-1, a CloudFront Function for SPA fallback and redirects.
Operations `site.deploy` (Build · Upload · Switch origin · Purge · Clean up) and `site.domain.add`. Mock: a mock CDN
that serves from the mock bucket.
