# 8.8 Static sites and CDN

Needs: phase 4 (buckets), 8.3 (builds). Overlaps roadmap 7.3 (bucket custom domains over HTTPS): this spec delivers
7.3's mechanism for platform sites, and 7.3 reuses it for the product's buckets.

## Requirements

1. **R1** A `static` workload builds with its runtime and build command and publishes a directory (`publishDir`,
   default `dist`) — no containers keep running.
2. **R2** Each deploy uploads to a new prefix (`<tenant>/<site>/<deployId>/`) in the region's static bucket, then
   switches the CDN origin path atomically; rollback is switching back. Old prefixes beyond the last 5 are deleted.
3. **R3** Served through **Cloud CDN** (backend bucket behind an HTTPS load balancer) or **CloudFront** (S3 origin with
   origin access control), on the platform host name and custom domains with managed certificates.
4. **R4** Cache: HTML `no-cache`, hashed assets `max-age=31536000, immutable`; deploys purge HTML paths.
5. **R5** SPA fallback (`index.html` for unknown paths) and redirects/headers from a `_redirects` / `_headers` file.
6. **R6** Metrics per site: bandwidth (of the plan's allowance), requests, cache hit rate.

## Design

Provider contract gains `cdn: { ensureSite(spec), setOrigin(ref, prefix), purge(ref, paths), addDomain(ref, host),
metrics(ref) }`. GCP: one global external HTTPS load balancer per install with a URL map entry per site, backend
bucket with Cloud CDN, Google-managed certificates. AWS: one CloudFront distribution per site (or per tenant when
limits bite), OAC on the bucket, ACM certificate in us-east-1, a CloudFront Function for SPA fallback and redirects.
Operations `site.deploy` (Build · Upload · Switch origin · Purge · Clean up) and `site.domain.add`. Mock: a mock CDN
that serves from the mock bucket.

### Sites the platform serves itself (decision, 2026-11-22)

Where there is no cloud CDN (a local site, spec 8.9, and the mock cloud) the platform is the origin, and a launcher
serves its sites through `services.platform.staticSites`:

- **Build once, export.** `site.create` / `site.deploy` (Build · Upload the files · Switch to the new files) build the
  image on one server (`build({ once: true })`), then the agent command `site.export` creates a container from it
  (never started, no network), streams `docker cp <c>:<workdir>/<publishDir> -` back as `chunk` frames (512 KB of
  base64 each, at most 512 MB) and removes the container. The controller checks the length and SHA-256 the agent
  reports. A missing folder fails the deploy: "There is no dist folder after the build: check that the build command
  writes the site there."
- **Content-addressed store** (`src/platform/sites.js`, `agent/tar.js`): files are kept once by SHA-256 under
  `static/sites/<tenant>/<site>/blobs/`, each deploy as a manifest (`deploys/<id>.json`: path → sha, size, type, and
  its `_redirects` / `_headers` rules). Links and paths outside the folder are skipped. Limits: 20,000 files, 250 MB,
  paths of 1,024 characters, 1,000 redirects, 200 header paths.
- **Atomic switch (R2).** `site.yaml`'s `current` is written once, after every blob and the manifest are stored, so a
  request sees all of one deploy or all of the other. The deploy before keeps serving while a deploy runs or fails.
  The current deploy and the last 5 others are kept; older manifests and the blobs only they named are deleted.
- **Rollback (R2)** is `staticSites.rollback(tenant, site, deployId)`: a new deploy record (`trigger: 'rollback'`,
  `serves: <deployId>`) that is live as soon as the switch is written; no build.
- **Serving (R4, R5).** `staticSites.respond(tenant, site, { method, path, query, headers })` → `{ status, headers,
  body, hit }`: GET and HEAD; ETags and 304; HTML `no-cache`, hashed names (`app-3f2a91c8.js`) `public,
  max-age=31536000, immutable`, others an hour; a folder without its slash → 301; `_redirects` (Netlify's format:
  `*` and `:name`, 200/301/302/303/307/308/404, `!` to win over a file) and `_headers` (Set-Cookie and the
  headers the platform sets itself refused), `site.spa` (paths with no extension get `/index.html`), `/404.html`; the rule files
  are not served; a suspended site answers 503. Files up to 4 MB are kept in memory (64 MB in all): those answers and
  304s count as cache hits.
- **Metrics (R6).** `staticSites.info()` gives requests, bytes and hits since the platform started; a launcher that
  proxies the site counts them per month itself (hero-co does).

The seeded `storefront` has a deploy's files (`src/seed/platform/static/`). The cloud adapters (8.8.3) keep this
contract for the deploy and swap the store and the serving for a bucket and a CDN.
