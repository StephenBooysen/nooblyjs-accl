# 8.7 Managed Key Value

Needs: phase 5 (database patterns). A new resource type, `keyvalue`, because its life cycle (no users, no backups
by default, memory not storage) differs from a database.

## Requirements

1. **R1** Create a Redis-compatible store: GCP **Memorystore for Redis** (Basic / Standard HA), AWS **ElastiCache for
   Valkey** (Redis OSS-compatible; single node or with a replica). Sizes Starter (1 GB), Standard (4 GB),
   Performance (13 GB).
2. **R2** Private only; reachable from chosen VMs in the same account, or for platform use from the tenant's hosts and
   network only; TLS in transit and AUTH token on.
3. **R3** Eviction policy (`allkeys-lru` default, `noeviction` for queues), persistence off by default (on: RDB
   snapshots daily on Standard and above).
4. **R4** Connection string `rediss://:<token>@<host>:6379`, revealed by audited reveal or linked as a secret
   (`REDIS_URL`).
5. **R5** Metrics: memory used (of total), connections (of max), ops/s, evictions, hit rate.
6. **R6** Screens: a **Key Value** section on the Databases page (cards like databases, Key Value badge); Create form
   with name, cloud, region, size, HA, eviction, persistence, VMs that can connect.
7. **R7** Platform API: `services.platform.keyvalue.create|get|list|resize|remove(tenantId, …)`.

## Design

Records `keyvalue/<name>.md` (`spec`: account, region, size, ha, eviction, persistence, allowVms; `ref`; `observed`:
status, host, port, memoryUsedMb; `tokenSecretRef`; `estimate`). Provider contract gains
`keyvalue: { create, get, resize, remove, setAccess, metrics }`; mock first. Operations `kv.create`, `kv.resize`,
`kv.delete` with steps Network access · Create · Auth token · Allow VMs. Catalogue prices per size and HA.
Delete is `approve`, confirm-typed, audited (product §7).
